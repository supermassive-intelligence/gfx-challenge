# T3.2 — MAME Lua harness: inject input scripts, dump frame hashes
Phase: 3   Depends-on: T3.1   Status: pending

## Context
MAME is the ground-truth oracle, used as a stock binary — never patched.
A Lua script replays our neutral input scripts inside MAME and dumps a
per-frame hash of video memory. Docs: docs.mamedev.org/luascript (input
fields, memory access via address space read, frame notifiers).

## Entry criteria
- [ ] T3.1 done (FROZEN schema; scenario scripts in `traces/scripts/`).
- [ ] Stock MAME installed locally; Berzerk ROM set runs in it (HUMAN-GATE:
      confirm version, pin it in cdoc/decisions.md).

## Task
`machine/tools/mame/replay.lua` + wrapper shell script:
1. Parse an input-script JSONL; on each frame notifier, apply due input
   changes by resolving port/field names through MAME's input manager
   (names must match — that's why the schema uses driver field names).
2. Per frame: hash VRAM + color RAM (NOT the rendered bitmap — avoids
   renderer differences; same definition as T3.3) and append
   `frame,hash` to an output file. Hash algorithm: pick one available in
   both environments (e.g. FNV-1a 64 implemented identically both sides);
   record choice in cdoc/decisions.md.
3. Set DIPs from the script header. Run headless/throttle-off; exit after
   the script's final frame.

## Out of scope
JS-side hashing (T3.3). Diffing (T3.4). Any MAME source modification.

## Definition of done
- [ ] Running the wrapper on the attract-only script produces a hash file
      with exactly the expected frame count.
- [ ] Same script run twice → byte-identical hash files (MAME-side
      determinism confirmed; if not, diagnose before proceeding — this
      invalidates the oracle).
- [ ] Works on at least two scenario scripts incl. one with real inputs.

## Verification
```
machine/tools/mame/run_replay.sh traces/scripts/attract.jsonl /tmp/a.hashes
machine/tools/mame/run_replay.sh traces/scripts/attract.jsonl /tmp/b.hashes
diff /tmp/a.hashes /tmp/b.hashes
```
