# T3.1 — Freeze input-script schema + JS recorder/player
Phase: 3   Depends-on: T2.9   Status: awaiting-human

## Context
Cross-platform deterministic input replay is the foundation of every
validation step from here on. Draft schema: `cdoc/schemas/input-script.md`
(resolve its open questions here, then mark FROZEN). MAME INP files cannot
replay outside MAME — this format is the substitute, consumed natively by the
JS machine and injected into MAME via Lua (T3.2).

## Entry criteria
- [x] T2.9 done (playable machine; HUMAN-GATE passed).

## Task
1. Resolve schema open questions (initial-state convention: recommend cold
   boot from reset; frame-0 semantics; multi-port naming). Update the schema
   doc, mark FROZEN, log decisions in `cdoc/decisions.md`.
2. `machine/src/script-player.js`: applies input records at vblank of the
   specified frame via `setField`; asserts script field names against T2.7's
   known-field registry.
3. Recorder in the browser shell: play with keyboard, dump script JSONL.
4. Record the first scenario library into `traces/scripts/`: attract-only
   (zero-input baseline), coin+start+first-maze, shoot-robot, player-death,
   maze-transition, ~60s free play. (HUMAN-GATE: human plays these.)

## Out of scope
MAME side (T3.2). Frame hashing (T3.3).

## HUMAN-GATE: What Sudnya must do

1. Serve the machine in the browser:
   ```
   cd machine && npx http-server -p 8080
   # open http://localhost:8080/shell/index.html
   ```
2. Load the Berzerk ROM set using the file picker.
3. For each scenario below, press **R** (or click "Record") to start, play the
   scenario, then press **R** (or "Stop") and click "Download script" to save
   the JSONL file.
4. Place each downloaded file in `traces/scripts/` with the names below.
5. Confirm each replays without field-name errors by running:
   ```
   node tools/replay-check.js traces/scripts/<filename>
   ```
   (This is a lightweight Node script that parses the JSONL and runs parseScript
   + ScriptPlayer construction; if it exits 0 the field names are valid.)

Scenarios to record:
| Filename                        | What to do                                    |
|---------------------------------|-----------------------------------------------|
| attract-only.jsonl              | Let the attract loop run ~60s, no input        |
| coin-start-first-maze.jsonl     | Insert coin (5), press 1P start (1), survive ~10s |
| shoot-robot.jsonl               | Enter a maze, shoot at least one robot         |
| player-death.jsonl              | Enter a maze, let a robot kill the player      |
| maze-transition.jsonl           | Clear a room and walk through the door         |
| free-play-60s.jsonl             | ~60s of free play                             |

Only Sudnya may flip this task to `done`. T3.2 and T3.3 do not depend on the
scenario scripts, only on the schema + player (both done). T3.4 does depend on
scenario scripts.
