# T3.3 — JS-side frame hashing + golden diff tool
Phase: 3   Depends-on: T3.1   Status: pending

## Context
Mirror of T3.2 on the JS machine, plus the comparison tool. Hash definition
must be bit-identical to T3.2's (same memory ranges, same algorithm, same
byte order) — defined once in `cdoc/decisions.md`.

## Entry criteria
- [ ] T3.1 done. Hash definition agreed (coordinate with T3.2 if it ran first;
      whichever task runs first proposes, second confirms).

## Task
1. `machine/tools/replay_hash.js`: headless; load ROMs, replay input script,
   emit identical `frame,hash` format (hash VRAM + color RAM at vblank).
2. `machine/tools/diff_hashes.js`: compare two hash files; on divergence
   report first divergent frame, run length, and (given the script) the
   nearest preceding input event — the debugging breadcrumb.
3. npm scripts: `npm run replay -- <script> <out>`, `npm run diffhash -- a b`.

## Out of scope
Recording golden files as fixtures (T3.4). Fixing divergences (T3.4 fallout).

## Definition of done
- [ ] JS determinism: same script twice → identical hash files (in `npm test`).
- [ ] `diff_hashes.js` unit-tested on synthetic divergent/identical inputs,
      exit codes 1/0 respectively.
- [ ] Hash function unit-tested against shared test vectors recorded in
      cdoc/decisions.md (the cross-platform contract).
