# T3.4 — Golden-frame gate: JS machine matches MAME
Phase: 3   Depends-on: T3.2, T3.3   Status: pending

## Context
THE Phase 3 exit gate and the project's standing regression suite. MAME hash
streams become committed goldens; the JS machine must match frame-for-frame.
This is the only test that validates timing, interrupts, and feel — unit
tests cannot. After this gate passes, traces from the JS machine are trusted
(plan Phase 4 may begin) and this suite runs after every future change.

## Entry criteria
- [ ] T3.2 and T3.3 done (both replay paths deterministic individually).

## Task
1. Generate MAME hash files for every scenario in `traces/scripts/`; commit
   as goldens in `machine/fixtures/goldens/` (decisions.md entry per CLAUDE.md
   golden policy, recording MAME version used).
2. `npm run golden`: replay all scenarios on the JS machine, diff against
   goldens, summary table, non-zero exit on any mismatch.
3. Drive divergences to zero. Expected debugging order: interrupt cadence
   (T2.6) → magicram ops (T2.5) → memory map details (T2.4) → core flag
   edge cases (T2.3). Log each root cause in cdoc/decisions.md — these are
   exactly the bugs that would have poisoned trace capture.
4. Wire `npm test` to include `npm run golden` when ROMs are configured.

## Out of scope
Trace capture (Phase 4). New scenarios beyond the T3.1 library (add later as
porting reveals coverage gaps).

## Definition of done
- [ ] `npm run golden` exits 0: every scenario matches MAME frame-for-frame.
- [ ] Goldens + MAME version pinned and committed.
- [ ] HUMAN-GATE: side-by-side play session (MAME vs browser shell) — human
      confirms indistinguishable feel. Then mark Phase 2–3 complete in
      `tasks/STATUS.md` and break down Phase 4+ into task files, adding the
      new task IDs to `cdoc/phase-task-map.md` in the same commit.

## Verification
```
cd machine && npm run golden
```
