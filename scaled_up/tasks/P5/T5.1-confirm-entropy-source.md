### nearest-label cross-reference of the in a,($4e) sites

```
0x023B  COLOUR_TEST_MODE (+59)        0x0608  BOOKKEEPING (+3)
0x0246  COLOUR_TEST_MODE (+70)        0x157A  MOVE_AND_DRAW_BOLT (+39)
0x0281  COLOUR_TEST_MODE (+129)       0x26B4  RANDOM-region / IRQ dispatcher (+60)
0x04A9  COLOUR_TEST_MODE (+681)       0x279D  WRITE_PATTERN (+80)
0x050C  COLOUR_TEST_MODE (+780)
0x0522  COLOUR_TEST_MODE (+802)
```

The load-bearing site is **0x26B4**, the interrupt service dispatcher
(`0x26B0: di; ld sp,$0840; push af; 0x26B4: in a,($4e); rra; jr c,$26d9`):
the V256/beam bit selects BOTTOM_OF_SCREEN_INTERRUPT (0x26D9) vs the mid-screen
path, and the mid-screen path (0x26B9+) increments a 2-byte interrupt-phase
counter at 0x089F/0x08A0, mixing in port 0x49.

### flow to placement

- RNG = LCG `RANDOM` @0x2678: `(0x435C) = 7*(0x435C) + 0x3153; return high byte`.
  Pure/deterministic in its seed. 13 call sites (V.LOOP, SR.TAB,
  ROBOT_ANIMATION_TABLES, COLLISION_DETECTION, GENERATE_ROBOT_SPEECH, ...).
- Timing enters via the **seed**: COLLISION_DETECTION @0x15CF clears the
  0x089F counter at game start (0x1645) and rewrites seed 0x435C (0x169A/0x16B9)
  then calls RANDOM (0x16BC). The interrupt dispatcher bumps 0x089F every
  non-vblank IRQ, so the mixed-in value is interrupt-phase-dependent.
- MAN_INIT (0x1FD4), CREATE_JOB (0x1E22), LTABLE (0x1AED) are job/dispatch
  scaffolding (LTABLE is a port-0x60 DIP-keyed jump table; CREATE_JOB a
  coroutine-stack op; MAN_INIT player init). None calls RANDOM directly; the
  task's hypothesis named them, but the actual RNG consumers are the
  movement/collision/speech routines above. Reported as found, not forced.

### finding (plain statement)

Evidence SUPPORTS "frame-242 divergence = timing-sensitive deterministic
entropy surfacing through the game's RNG", with one correction to the
hypothesis: the source is **the V256/beam read in the IRQ dispatcher (0x26B4)**
feeding the interrupt-phase counter at 0x089F -> LCG seed 0x435C, **NOT** the R
register. `ld a,r` does not appear in the ROM at all, so the R-register RNG
theory is eliminated; port 0x4E is the only timing-sensitive entropy read
present. No evidence of a data/machine bug in the RNG path: the LCG arithmetic
is ordinary and deterministic.

LIMIT (why this is a HUMAN-GATE, not a self-cert): this confirms the entropy
*mechanism*. It does not prove the specific T3.4 frame-242 single-byte shift
(VRAM 0x5DE3, one-frame phase shift on an erase-write, attract/no-input) flows
through this RNG path rather than being a direct artifact of IRQ-delivery timing
on a deterministic draw routine. Both reduce to the same root cause (accumulated
cycle-timing / interrupt-phase drift), which is the deferred timing-parity work.
