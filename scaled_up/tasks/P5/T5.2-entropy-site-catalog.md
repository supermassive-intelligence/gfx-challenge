### Static (frozen decode oracle, decimal bytes)

65 IN instructions total: 54 `in a,(n)` (DB nn = [219,nn]) + 11 `in a,(c)`
(ED 78 = [237,120]). Ports read by `in a,(n)`: 0x44,0x48,0x49,0x4A,0x4C,0x4D,
0x4E,0x60-0x65,0x66,0x67, and 6 false-positive 0x4E... no — and 6 `in a,($ff)`
(data-region mis-disassembly).

### Dynamic (heavy trace + exact-PC IO capture over 4 scripts)

- Heavy trace reproduced T4.1 exactly: attract-only = 416,482 invocations.
- Distinct ports the CPU actually reads: 0x44, 0x49, 0x4A, 0x4C, 0x4D, 0x4E,
  0x60, 0x61, 0x65, 0x66, 0x67 + mem entropy reads 0x089F/0x08A0/0x435C.
- Port 0x48 (P1) never read in any script — explained (game never credited;
  CPU first polls SYSTEM at frame 573, scripts release coin/start before then).
- Entropy reads: 0x4E@0x26B4 (V256) fired 5020x; counter 0x089F/0x08A0 read
  2512x @0x26BE/0x26C0; seed 0x435C read 115x @0x267B (attract counts).

### Reconcile + classify

Every dynamic IO read maps to a static site (reading PC = static_site+1). Every
non-firing static site explained by 3 non-entropy buckets (service menus /
unreached gameplay / 0xFF data). Single timing-locked entropy source confirmed:
port 0x4E bit0 (V256) at the IM2 dispatcher 0x26B4; refinement vs T5.1 — the
other 0x4E reads consume bit7 (collision flop, draw-deterministic), not V256.
