## Approach / decisions (this session)
- `machine/ports/z80flags.js` -- exact Z80 8-bit ALU flag helpers (sub/cp/and/or/
  xor/add/inc/dec/addHL16), including the undocumented X/Y rules (CP takes X/Y from
  the OPERAND, not the result). Validated against the captured records via the bench.
- Hook extension (`src/port-hook.js`): a port may set `ctx.cycles` to the exact cost
  of the PATH it took (branching routines); `PORT_META.maxCycles` is the worst-case
  used for the interrupt-decline gate. Straight-line routines keep a single `cycles`.
  This preserves the T9.1 cycle/interrupt-cadence guarantee for path-dependent cost.
- Bottom-up composition: a routine that falls into / would CALL an already-ported
  leaf is implemented by invoking that leaf's port (e.g. 0x2b39 -> SET_VELOCITY).
- INNER-CALL VRAM RESIDUE (batch 2, new): a port that elides a routine's inner
  `call X` must still replay the 2-byte residue that `call` leaves on the
  VRAM-overlapping stack (the pushed return address; the matching `ret` pops sp but
  the bytes stay on screen). PORT_META.pushes now accepts a NUMBER (the residue
  value = last inner call's return address) alongside register names. Found via
  0x1997: fast-path diverged at coin-start frame 584 (the 2-visible-byte signature)
  because the real 0x1997 does `call $18E0` (pushes 0x199A); declaring pushes:[0x199a]
  restored byte-transparency. 0x157e has the same shape (inner `call $1597`, residue
  0x1593) and passed WITHOUT it by luck -- now declared so it matches deterministically.
- SHARED-BODY ROUTINES (batch 3): 0x29a1 (RTOAX) is literally `ld b,$90` then falls
  straight into 0x29a3 (CALCULATE_MAGIC_IMAGE_RAM_ADDRESS) -- identical body, only B
  differs on entry. Ported once: 0x29a1's port sets b=0x90, calls the shared body,
  and charges +7 cycles for the extra `ld b`. Two routines, one implementation.
- INLINE-PARAMETER HAZARD (batch 3, flagged not ported): COLOUR_FILL (0x3657) and
  PRINT_STRING_297B (0x297b) start with `pop hl` to grab the return address, read
  inline data bytes that follow the `call` (incrementing hl), then `ret` to the
  address PAST that inline data. The T9.1 hook's RET model returns to the bytes AT
  entrySp (i.e. into the inline data, executing it as code) -- so these CANNOT be
  hooked without a per-routine "consumed N inline bytes" return adjustment. Left
  unported; moved to a new INLINE-PARAM hazard bucket below.
- BENCH-UNEXERCISED PATHS (batch 3): the magic-image routines have a FLIP (cocktail)
  branch the captured records never take (all records have 0x4379==0). Implemented
  from the disassembly but NOT bench-covered; only the live hooked==un-hooked
  regression guards it if a script ever flips the screen. Noted in the port file.
- bit n,(hl) WZ HAZARD (batch 4): a routine that `ret`s directly after `bit n,(hl)`
  exposes that op's undocumented X/Y flags, which come from the Z80 internal WZ
  register (proven: 0x3719 record #0 has (hl)=ROM[0]=0x00 yet f_out Y=1). The port
  ctx has no WZ, so its return F is not reproducible -- such routines are NOT portable
  here (defers 0x3719, 0x27a9). `bit n,(iy+d)` is fine (X/Y from the known (iy+d)
  high byte); a `bit n,(hl)` used only as a mid-routine branch is fine (F never
  observed). See decisions.md 2026-06-18.
- DATA-DEPENDENT LOOP COST (batch 4): 0x27f5 walks a variable-length list; the port
  accumulates exact T-states into ctx.cycles (the 127-cycle short path reconstructs
  as prologue 37 + one node 90). maxCycles is set to the worst case observed over the
  5 scripts (1242); because the test plan is generated FROM those scripts, live actual
  is bounded by it, and the decline gate only ever errs toward more declines.
- HOOK FIX -- POST-PORT PUSH-RESIDUE CAPTURE (batch 5): the dispatcher now reads
  PORT_META.pushes register values from the OUTPUT bank (after applyCtx), not the entry
  bank. For a balanced `push X ... pop X` frame the VRAM residue byte == X_out (the pop
  restores the push-time value into X). Entry-bank capture was only coincidentally right
  (prior ports push registers they do not modify). PRINT_CHAR `push af` AFTER an ADD HL
  chain changes F, so its residue F-byte is f_out not f_in -- entry capture diverged
  (coin-start frame 582). Post-port capture is provably equivalent for all prior ports
  (97/97 + 5/5 still green) and correct here. See decisions.md 2026-06-18.
- FAITHFUL-TRANSCRIPTION PORTS (batch 5): when a routine's return flags AND shadow bank
  are load-bearing and subtle (PRINT_CHAR: f_out from an ADD HL chain saved by push af;
  9-row counter carried in shadow AF via ex af,af', so a_p_out/f_p_out are compared),
  port by simulating the real opcodes with the z80flags helpers rather than deriving
  flags by hand. The flags fall out exact; the bench confirms a_p/f_p too.

- NON-LOCAL RETURN HAZARD (batch 6): a routine whose success path executes `pop hl;
  ret` (or otherwise drops extra stack levels) returns to its GRANDPARENT, not its
  caller. The T9.1 hook always does a single `ret` (pop entrySp, sp+=2), so it cannot
  reproduce a port that sometimes returns two levels up. 0x15cb (FITS_IN_BOX-style
  check) is the first such case found -- its early-exit paths (`ret z/m/nc`) are normal
  single returns but the success path does `pop hl; ret`. Needs a hook extension (a
  port-signalled "extra frames to drop" + matching pops) before it can be hooked.
- FAITHFUL-TRANSCRIPTION, FIXED-COST LEAF (batch 6): C_LOAD (0x1776) -- a clean leaf
  with no shadow/flag subtlety beyond a final `add a,$40`; both djnz counts are
  immediates so cost is path-independent (642 T-states, hand-summed = record cycles,
  which doubles as a disassembly-completeness check). `out (c),r` ports = C masked to
  low 8 bits (matches the bench + Berzerk decode); `res`/`set`/`djnz` are flag-neutral.

- IFF NOT MODELED + push-iy RESIDUE (batch 7): RESET_JOBS (0x22f1) -- a clean leaf
  that brackets its body in `di`...`ei`. IFF (the interrupt flip-flop) is NOT a compared
  register and nets to no change (di then ei), so the port ignores it; the live hook
  already preserves interrupt CADENCE by charging the full displaced window (1612 T) and
  declining when an interrupt event would split it. Its `push iy; pop hl` is a balanced
  frame whose push leaves IY on the VRAM-overlapping stack; IY is unchanged so output
  bank == input bank and PORT_META pushes:['iy'] replays it. Fixed cost 1612 T (single
  path; the only loop's djnz count is the immediate $38); hand-sum reconciled to the
  record once `pop hl` was correctly costed at 10 T (not 14).

## Option 2 -- hooked/callee-included (INCLUSIVE) heavy-trace mode  [BUILT + de-risked; adoption gated]

WHY (decisions.md 2026-06-20 later, Decision C): ~25 of the remaining portable routines
are non-leaf composites. The leaf-first generator excludes them (a standalone replay
re-executes callees inline, so an exclusive record -- callee accesses split out per
heavy-trace.md note #4 -- mismatches). Restoring a hermetic bench bar for composites makes
the bottom-up port verifiable per-routine, not transparency-only.

DESIGN (minimal, additive): `captureTrace({inclusive:true})` attributes each mem/IO access
to EVERY open frame (the full subtree closure) instead of only the innermost. Each
invocation's record then includes its callees' accesses, so the generator's self-check
(which replays the real routine with callees inline) reproduces it -> composites
self-validate. Leaves are unchanged (no children). Interrupted invocations fold the ISR's
accesses in and so fail their interrupt-free replay -> still excluded (as today). Threaded
through `generateTestPlan({inclusive})` and the CLI `--inclusive` flag. The composite PORT
(which composes already-ported sub-ports) is then benched against the inclusive record.
