# T9.1 — Port hook harness (CALL-address replacement)
Phase: 9   Depends-on: T8.1   Status: blocked

## Context
Plan Phase 9 infrastructure: let a JS routine run in place of the Z80 routine
at a given CALL address, sharing the same memory object (T2.4), with the Z80
core executing everything else. Game stays fully playable; one routine swapped
at a time.

## Entry criteria
- [ ] T8.1 done (bench green on sample routine).
- [ ] Golden-frame suite (T3.4 scoped) runnable as regression.

## Task
Add a dispatch hook in the machine: when PC hits a registered CALL target,
run the JS implementation (reads/writes shared memory, returns as if RET),
else fall through to the Z80 core. Registry of {address → JS fn}. One trivial
leaf routine ported end-to-end as the proof.

## Out of scope
Porting the full routine set (T9.2). Removing the core (T10).

## Definition of done
- [ ] One leaf routine runs via JS hook; its bench cases pass.
- [ ] Scoped golden-frame suite still green with the hook active.
- [ ] Hazard checklist documented (self-modifying code, computed jumps, jump
      tables, timing-contract routines, entropy reads from T5.2).

cd machine && npm test && npm run golden
