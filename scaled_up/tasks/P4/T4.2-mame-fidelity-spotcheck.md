# T4.2 — MAME routine-level fidelity spot-check
Phase: 4   Depends-on: T4.1   Status: done (Sudnya signed off 2026-06-17)

## Context
T4.1 built and verified the heavy-trace capture (capture runs, deterministic,
read-set ordered, callerPCs all real CALL/RST). What is NOT yet proven is that a
captured routine's behavior matches MAME at the ROUTINE level. This is the gate
before heavy-trace.md is FROZEN and T4.1 moves to awaiting-human/done.

Within the deterministic window (frames 0-258, per T3.4 sign-off) JS and MAME are
in lockstep, so routine I/O can be compared exactly there.

## Entry criteria
- [x] T4.1 capture tool present + verified (machine/tools/heavy_trace_capture.js).
- [ ] MAME runnable with a Lua hook (tools/mame/ harness exists from T3.2).

## Task
Pick 3-5 routine invocations that occur wholly inside frames 0-258 and use
ORDINARY CALL/RET (NOT coroutine/dispatch routines). Recommended: RANDOM 0x2678
(LCG, leaf); plus 2-4 other leaf/arithmetic routines. For each:
- JS side: extract the invocation record(s) from a heavy-trace capture.
- MAME side: a small Lua hook logs the same fields (regs_in at entry, ordered
  mem/IO reads, regs_out at return, writes) for the same invocation.
- Diff regs_in / read_set / regs_out / write_set; they must match EXACTLY.

AVOID for this check (known to mis-nest, per heavy-trace.md): CREATE_JOB 0x1E22,
MAN_INIT 0x1FD4, LTABLE 0x1AED, and the attract main loop (0x188b).

## Out of scope
Fixing the capture for coroutine routines (Phase 9 port-time concern). Freezing
the schema (that is the follow-on step on pass). Cycle-timing work.

## Result
PASS (machine work complete; HUMAN-GATE freeze sign-off recorded — Sudnya
reviewed the pasted comparisons and directed the freeze on 2026-06-17). Full
detail + literal commands in cdoc/decisions.md (2026-06-17 T4.2 entry).

Method change (forced by evidence, ruled by Sudnya): frames 0-258 contain ZERO
ordinary CALL/RET invocations (pure POST); first ordinary routines run ~frame
574, RANDOM 0x2678 ~frame 982. So same-invocation/frame pairing is impossible
and the routines run past the deterministic window. Adopted STATE-KEYED pairing:
pair JS<->MAME invocations of the same routine by consumed inputs (read regs +
data reads), exclude R, SP as net-delta, strip stack, read_set compared
data-aware (see schema note #6).

Tools (new): machine/tools/mame/routine_trace.lua (MAME hook: whole-program
read/write taps; entry only on a genuine opcode fetch, PC==fetch addr; SP-depth
exit) and machine/tools/routine_fidelity_diff.js (state-keyed comparator).

Routines (4), all verified leaf + no-IO vs the decode oracle:
- RANDOM 0x2678  -> ALL PAIRS byte-EXACT (read_set incl fetches, regs_out,
  write_set). LCG chain JS==MAME: 0x0202 -> 0x3F61 -> 0xECFA -> 0xAC29.
- 0x18e0         -> EXACT.
- 0x287f         -> EXACT.
- 0x1ce7         -> regs_out + write_set EXACT; read_set differed ONLY by the
  not-taken JR cc displacement bytes = schema note #6 artifact (harmless;
  unused operand). regs_out match proves no branch-direction divergence.

Literal MAME command:
