# T2.5 — Video: VRAM, magicram, color RAM, intercept flag
Phase: 2   Depends-on: T2.4   Status: pending

## Context
The heart of Berzerk's rendering AND collision detection. Writes through the
magicram window pass through a hardware shifter/flipper (74181 ALU ops)
before landing in VRAM; the intercept flag latches collisions for the CPU to
read back. Spec: `cdoc/hardware-berzerk.md` §4 (video) and §3 (intercept read
port). Get this wrong and gameplay is subtly broken everywhere.

## Entry criteria
- [ ] T2.4 done (`npm test` passes; device handler hooks exist).

## Task
`machine/src/video.js`: VRAM store; magicram write path implementing the
shift/flip/ALU-op behavior per spec table; color RAM with documented block
granularity; intercept flag set/clear semantics incl. the read-port clear
behavior; a `renderToRGBA(buf)` that rasterizes VRAM+colorRAM to a pixel
buffer (used by the browser shell and by framebuffer hashing in Phase 3).

## Out of scope
Screen timing/interrupts (T2.6). Browser canvas (T2.9). Performance tuning.

## Definition of done
- [ ] Table-driven unit tests: for each magicram control value, write a known
      byte pattern, assert resulting VRAM bytes (cases hand-derived from the
      spec doc; cite spec section in each case).
- [ ] Shift-across-byte-boundary cases tested (the classic bug).
- [ ] Intercept flag: set on collision case, cleared per spec, tested.
- [ ] Color RAM block addressing tested at block boundaries.
- [ ] `npm test` passes.
