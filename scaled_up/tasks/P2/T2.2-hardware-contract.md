## Context
We read ONE MAME source file per game as documentation (never port its C++):
`src/mame/stern/berzerk.cpp` from the mamedev/mame GitHub repo. Output is the
authoritative spec all device tasks (T2.4–T2.8) cite, so wrong/vague entries
here become bugs there. MAME itself stays an unmodified black box.

## Entry criteria
- [ ] Network access to github.com/mamedev/mame (or a local MAME source copy).

## Task
Write `cdoc/hardware-berzerk.md` covering, each with the driver line numbers
it was derived from:
1. CPU: type, clock; ROM/RAM regions and sizes.
2. Memory map: every range in the program address map (ROM, RAM, VRAM,
   magicram window, color RAM) with mirror/size details.
3. IO port map: every port, direction, function (incl. intercept/V256 read,
   IRQ enable, sound/speech latches).
4. Video: framebuffer geometry, pixel format, magicram shifter/flipper
   behavior (74181 ops table), color RAM block granularity, intercept flag
   semantics.
5. Interrupts: NMI and IRQ sources, enable conditions, scanline/timer cadence,
   vectors.
6. DIP switches and input port field names (exact MAME names — the input
   script schema depends on them).
7. Sound/speech: S14001A command interface as seen by the CPU (which writes
   trigger which utterances), other sound ports. Note: we will play samples,
   not emulate the chip — record only the CPU-visible contract.
8. Nondeterminism candidates spotted while reading (seed list for Phase 5).

## Out of scope
Implementing anything. Copying MAME code into the doc — describe behavior in
our own words/tables.

## Definition of done
