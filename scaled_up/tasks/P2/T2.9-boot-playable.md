# T2.9 — Boot to playable game (browser shell)
Phase: 2   Depends-on: T2.3, T2.4, T2.5, T2.6, T2.7, T2.8   Status: pending

## Context
Integration milestone: all components assembled into a machine that boots the
real ROM and plays. This is the Phase 2 exit gate. Expect to find cross-
component bugs here — that's its job.

## Entry criteria
- [ ] T2.3–T2.8 all done (`cd machine && npm test` green including ZEX gate).
- [ ] Berzerk ROM set available locally (user-supplied path).

## Task
1. `machine/src/machine.js`: compose CPU+memory+video+scheduler+input+sound;
   `reset()`, `runFrame()`, `loadRoms(paths)`.
2. `machine/shell/index.html` + minimal JS: canvas blit of `renderToRGBA`,
   requestAnimationFrame pacing at the original frame rate (scheduler stays
   wall-clock-free; the shell paces it), keyboard → `setField` mapping,
   WebAudio backend hookup. Serve via `npx http-server` or equivalent —
   no build step.
3. Headless smoke test: boot ROM, run N frames, assert VRAM is non-trivial
   (attract mode drew something) and CPU hasn't halted/wedged.

## Out of scope
Golden-frame validation vs MAME (Phase 3 — playability here is necessary,
not sufficient). Trace capture (Phase 4). Performance beyond "hits frame rate
on a laptop".

## Definition of done
- [ ] Headless smoke test passes in `npm test` (skips gracefully if ROM path
      not configured, with clear message).
- [ ] HUMAN-GATE: human plays in browser — boots to attract mode, coin/start
      works, full game loop (move, shoot, die, next maze) playable, speech
      samples fire at sensible moments.
- [ ] Defects found are filed as notes in this task file, fixed or accepted.

## Verification

cd machine && npm test        # plus the HUMAN-GATE play session
