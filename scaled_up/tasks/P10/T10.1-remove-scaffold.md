## CONSTRAINT surfaced in T9.2 (atomic-routine hazard -- read before building native)
A ported routine LONGER than the inter-interrupt gap (~4000 T-states = 41666 T/frame /
~10 interrupts) CANNOT be run as a single atomic JS call in the NATIVE target. The real
routine spans several interrupt boundaries; an atomic JS port defers those interrupts to
AFTER it, so the ISR reads V256 (port 0x4E bit0) at a shifted beam position -> the entropy
phase (0x089F counter -> 0x435C LCG seed -> RANDOM @0x2678) drifts -> object placement
diverges. The Phase-9 interrupt-decline gate ALREADY declines these routines (they show 0
live fast-path dispatches, e.g. 0x2a40 PRINT_DIGITS ~8800 T); that decline is the symptom.
For the native target they need the SAME cooperative interrupt-interleaving / yield model
as the Tier-3 coroutine substrate -- they must yield at their original interrupt-check
points, not run to completion. "Registered in Phase 9" != "native-ready": the Phase-9
fast-path-vs-decline split IS the Phase-10-readiness split. Routines that genuinely fast-
path in Phase 9 (< ~4000 T: 0x1553, 0x15a0) can run atomically in native; routines that
always decline (0x2a40 and any future long/loop-heavy composite) require the yield model.
See cdoc/decisions.md 2026-06-21. The native main loop therefore needs a cooperative
scheduler that can suspend a long ported routine at its interrupt-check points -- not just
a flat "call each ported routine to completion" loop.
