# T6.1 — Trace-driven annotation
Phase: 6   Depends-on: T4.1, T5.2   Status: blocked

## Context
Plan Phase 6: understand the program from traces alone (method must generalize
to source-less games). Walk the call graph bottom-up; infer each routine's
purpose from read/write addresses (cross-referenced with the hardware contract
+ entropy catalog), argument registers, and observed effects.

## Entry criteria
- [ ] T4.1 done (traces + call graph).
- [ ] T5.2 done (entropy sites known, so "random" reads aren't mis-annotated).

## Task
Produce annotated assembly + a RAM variable map (addr → name → meaning) for
every trace-reachable routine. Name routines by behavior, not guesswork.

## Out of scope
Porting (T9). Scoring vs Frenzy source (T6.2). Routines never seen in traces
(leave flagged, not invented).

## Definition of done
- [ ] Every trace-reachable routine has a name + contract (inputs/outputs/
      side-effects).
- [ ] RAM variable map committed.
- [ ] HUMAN-GATE: Sudnya spot-reviews a sample of annotations vs traces.
